# bankee-kya-os

End-to-end agentic payment infrastructure secured with [KYA-OS](https://github.com/decentralized-identity/kya-os-mcp) — the DIF TAAWG protocol for agent identity, delegation, and audit trails.

```
Agent calls create_payment £500
  → Payment server: needs_authorization (consent gate fires)
  → Human approves at consent UI
  → Consent service issues W3C Delegation VC
  → Payment server stores VC, agent retries
  → Payment executes with JWS proof attached
  → Audit service records proof record
  → ProofVerifier validates the full chain
```

## Services

| Service | Port | Purpose |
|---------|------|---------|
| **Payment MCP Server** | 3001 | Exposes 5 payment tools over SSE + Streamable HTTP |
| **Consent Service** | 3002 | Human-in-the-loop approval UI + W3C VC issuance |
| **Audit Service** | 3003 | Proof record ingestion, query, live dashboard, verification |

## Quick Start

```bash
# 1. Install dependencies
npm install

# 2. (Optional) Generate a persistent DID that survives restarts
npm run generate-identity

# 3. Start all three services
npm run start:all

# 4. In a new terminal: run the full end-to-end demo
npx tsx src/demo-agent.ts
```

The demo runs 11 steps automatically and prints the results to the console.

### What you'll see

```
Step 1  — Connect + KYA-OS handshake (session established)
Step 2  — get_balance           → proof attached
Step 3  — get_exchange_rate     → proof attached
Step 4  — create_payment £50    → autonomous (below threshold), proof attached
Step 5  — create_payment £500   → blocked: needs_authorization returned
Step 6  — Human approves        → W3C Delegation VC issued to agent DID
Step 7  — Retry create_payment  → auto-applies VC, payment executes, proof attached
Step 8  — get_payment_status    → proof attached
Step 9  — list_payments         → proof attached
Step 10 — Audit trail           → all proof records queried
Step 11 — Proof verification    → ProofVerifier validates JWS signature
```

After the demo: open `http://localhost:3003` for the live audit dashboard.

## Payment Tools

| Tool | Delegation | Description |
|------|-----------|-------------|
| `get_balance` | None (proof only) | Current wallet balance |
| `get_exchange_rate` | None (proof only) | Live FX rate (GBP/USD, GBP/EUR, GBP/USDC) |
| `list_payments` | None (proof only) | All payments in this session |
| `get_payment_status` | None (proof only) | Status of a specific payment |
| `create_payment` | Required if amount > £100 | Create a payment with optional consent gate |

## KYA-OS Features Demonstrated

| Feature | Where |
|---------|-------|
| **Agent DID** (`did:key`) | Auto-generated by `createKyaOsMiddleware` on payment server startup |
| **Session handshake** | `_kyaos` tool, nonce-based replay protection (§3 of spec) |
| **Detached JWS proof** | Every tool response via `wrapWithProof` (§5) |
| **Consent gate** | `wrapWithDelegation` with `formatChallenge` on `create_payment` (§6) |
| **W3C Delegation VC** | `DelegationCredentialIssuer` in consent service (§4) |
| **Delegation store** | Resume-token pattern, auto-apply on retry |
| **`AuditLogProvider`** | `buildAuditRecord` called after each tool call (§12.4) |
| **`ProofVerifier`** | Offline JWS verification in audit service (§5.3) |
| **did:web support** | Set `IDENTITY_PATH` and persist with `npm run generate-identity` |

## Architecture

```
┌─────────────────────┐   MCP/SSE    ┌────────────────────────────────┐
│   Demo Agent        │◄────────────►│   Payment MCP Server :3001     │
│   (demo-agent.ts)   │              │   ┌──────────────────────────┐  │
└─────────────────────┘              │   │ createKyaOsMiddleware    │  │
                                     │   │ wrapWithProof            │  │
         Human                       │   │ wrapWithDelegation       │  │
           │                         │   │ DelegationStore          │  │
           ▼                         │   └──────────────────────────┘  │
┌─────────────────────┐  POST VC     └──────────────┬─────────────────┘
│  Consent Service    │◄─────────────────────────────┘
│  :3002              │
│  GET  /consent      │  Webhook POST
│  POST /api/approve  │──────────────►┌──────────────────────────────┐
└─────────────────────┘               │  Audit Service :3003          │
                                      │  POST /api/records            │
                                      │  GET  /api/records            │
                                      │  POST /api/verify             │
                                      │  GET  /  (dashboard)          │
                                      └──────────────────────────────┘
```
